Modes and the operator's controls

The implement journey walks through this use case with a mental model and a diagram. The extension restricts nothing while no stage runs. It registers one command, /journey. Bare /journey opens a picker; /journey <name> skips it, and Tab completes the names. One command table in src/index.ts feeds the picker, the completions, and dispatch, so a new mode is one entry.

EntryKindBehavior
implementModeTurn on journey_plan, ask the Pi agent to draft a plan from the conversation or a named source, and open the approval dialog once the Pi agent finishes. A digest opens the dialog for a recorded plan; a digest with --allow-checks approves it without a dialog
pingModePlaceholder. Send ping to the Pi agent, which answers
status, stop, resume, retireControlReport, cancel and drain, continue, or retire the unfinished run. The picker offers only the controls that apply

Only an operator command or dialog approves a plan, and approval binds to the plan digest. A replaced plan, a tree navigation, or a session transition revokes an open dialog. The dialog lists each unit's writable paths and commit message in full, the checks with their declared effects, and the delivery. While a stage runs, the Pi agent keeps read, grep, find, and ls, and shell commands are refused.

Ownership, recovery, and uncertainty

Workers receive scoped read and edit tools and no shell, Git, credential, or GitHub authority. The coordinator owns commits, checks, pushes, and PRs. Path admission checks canonical targets, symlinks, repository metadata, and writable scope, and each read-modify-write is serialized. Configured checks run repository code; approving them trusts their declared effects. This is an enforced boundary for mediated file tools and owned jobs, not an operating-system sandbox.

The journal lives under the checkout's Git directory at pi-journey/. A process lease prevents a second coordinator, and each owned command has an IPC supervisor that kills its process group when the coordinator dies. The coordinator records intent before each branch, commit, push, or PR effect and confirms it afterward. Restart inspects Git and GitHub before resuming and never replays an uncertain effect. Dirty files after a crash need explicit acceptance, which admits only attributable in-scope edits. Stopping closes admission, cancels, and waits for workers and processes to exit. Pi ignores a navigation handler that throws, so the extension returns an explicit cancel when owned work cannot drain.

A worker session builds its own model runtime, which cannot see providers that extensions registered in the parent Pi session. Preflight resolves the worker model through that runtime and blocks before any work when it cannot.

Local checks and merging

This repository follows the routine of pascalandy-blog-paper and skills. just check is the local verdict. lefthook runs gitleaks and Biome on staged files before each commit and just check before each push. CI runs only when started by hand. just signoff posts a green signoff status on the tested, pushed commit, and a GitHub rule requires it before a merge into main. just merge signs off and merges exactly that commit, and only after an explicit authorization. A journey never merges; merging belongs to the project.
